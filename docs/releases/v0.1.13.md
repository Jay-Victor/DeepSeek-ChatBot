v0.1.13 在 v0.1.12 基础上加入「上下文与压缩」：较早对话可以总结成摘要，按阈值自动或手动控制上下文占比，原始消息仍保留、可撤销。

## 应用

- 包名 `com.deepseekchatbot`，`versionCode 14`
- minSdk 26 / targetSdk 36 / compileSdk 36
- Release APK 5.34 MB，v2 签名

## 本版新增

### 设置 · 上下文与压缩

- 自动压缩开关，默认关闭
- 压缩阈值：默认 50%，范围 1–99；上下文占用超过该比例时触发
- 压缩目标：默认 20%，必须小于阈值；压缩后希望达到的占比
- 底部按 1M 窗口换算预览，例如「超过 50%（约 500,000 tokens）时自动压缩，压缩到约 20%（约 200,000 tokens）以内」

### 占用卡片与手动压缩

- 输入框占用卡片新增「压缩对话」；压缩中显示分块进度，可取消
- 完成后显示已压缩轮数与估算 token，可展开摘要、可撤销；撤销即恢复完整上下文
- 卡片新增「较早摘要」行；「系统与模板」不再包含摘要 token
- 摘要由模型生成，覆盖点之前的轮次不再进入请求，原始消息一条不删

### 自动压缩

- 回复结束或打开会话时检查当前会话；每次占用变化最多尝试一次
- 同一会话 5 分钟内不重复自动尝试，手动压缩后也不会被立刻再压一次
- 语音模式收起占用环时，自动检查延后到切回文本输入或重开会话

### 请求与分支

- 摘要放在 `system` 的 `<earlier_conversation_summary>` 段，不伪造 user / assistant 轮次
- 发送、重新生成、编辑提问、续写、附件重试五处请求入口统一按 `throughMessageId` 裁剪历史
- 在压缩覆盖点之前重新生成、编辑提问或切换分支时摘要自动失效；切回原分支后恢复
- 消息列表在覆盖点后的第一条消息前显示「已压缩 N 轮较早对话」分隔条

### 变更

- 移动端设置新增第四个分组后，390 宽下四个分组仍能全部排下，不再横向滚动
- 压缩前测得的服务端用量不再显示为压缩后上下文的 measured，避免展示过期数字

## 已知限制

- 摘要会产生额外的模型请求；阈值设得低或会话很大时 token 消耗会上升
- 压缩目标是软目标：最近一轮本身超过目标时，压缩后仍可能高于目标
- 压缩只保留单条记录：在覆盖点之前切分支会让摘要失效；在另一条分支再压缩会覆盖前一条
- ZIP 导入导出不携带压缩摘要，导入后回到完整上下文
- 被压缩轮次的图片 / PDF 只以文件名和当时讨论过的文字进入摘要，图片内容本身不会保留
- 真机安装、数字输入法与 WebView 键盘行为仍待设备验收

## English

v0.1.13 adds context compression to the Android WebView build of chat-demo. Settings → Context & compression controls automatic summarization with a 50% threshold and a 20% target by default. The usage popover can compress manually, shows progress and the summary, and supports undo; requests carry the summary plus recent rounds while original messages stay local. Compression follows the current branch and is not included in ZIP export/import. Install with `adb install -r`; minSdk 26, MIT licensed, upstream notice kept in `web/LICENSE`.
